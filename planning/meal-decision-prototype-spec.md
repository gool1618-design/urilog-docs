# 献立決定アプリ(仮) プロトタイプ仕様: 決定フロー(気分・二択・決定)

> 第3版の方針(決めることだけに特化、レシピは持たない)に合わせて更新。料理詳細画面は無くし、「決まった」画面が材料メモと「レシピを見る」を担う。

- 目的: 「30秒・3タップで決まる」を自分で1週間使って確かめる。見た目の仕上げより、流れと手触りの検証を優先する
- 範囲: ホーム(最小) → 気分・時間 → どっち?(二択) → 決定 → 決まった(最小)。買い物・履歴・設定・グループ・1週間ぶん作る は範囲外(「1週間ぶん作る」は自己テスト後、スコアが固まってから足す)
- データ: `meal-decision-dishes.csv` の150件を仮JSON化して同梱(主な材料名まで。分量と手順は持たない)。画像は仮の単色プレースホルダーでよい
- 技術: SwiftUI、iOS 17以上。永続化は UserDefaults に「今日は違う」と履歴だけ(プロトタイプ段階)

---

## 1. 流れと状態

```
Home ──[決める]──▶ Mood ──[候補を見る / スキップ]──▶ Duel(1回目) ──[タップ]──▶ Duel(2回目) ──[タップ]──▶ Decided
 │                                                        │                                             │
 └──[疲れた日]──▶ Omakase(演出) ─────────────────────────┘                                    ├─[これにする]──▶ Done
                                                                                                ├─[別の候補を見る](残り2→1→0)──▶ Duel(1回目)へ戻る
                                                                                                └─[おまかせで決める]──▶ Omakase ──▶ Decided(残り回数0で固定)
```

### 状態(DecisionSession)

| 項目 | 型 | 説明 |
|---|---|---|
| mood | enum? | hearty / light / warm / noodleRice / nil(なんでも) |
| timeLimit | enum | quick(〜15分) / normal(〜30分) / any |
| relaxation | 0〜2 | 緩和段階。0=なし、1=時間を広げた、2=気分も外した |
| pool | [Dish] | フィルタ後、スコア順に並んだ候補 |
| shown | Set<DishID> | このセッションで表示した料理 |
| softNo | Set<DishID> | 二択で選ばれなかった料理(今日は違う) |
| round | 1 / 2 | 二択の何回目か |
| left, right | Dish | 現在の2枚 |
| winner | Dish? | 直前の勝者 |
| redrawsLeft | 2 → 0 | 「別の候補を見る」の残り回数 |
| decided | Dish? | 決定した料理 |
| startedAt | Date | 計測用 |

### セッションの寿命

- アプリを開いて「決める」を押した時点で生成。決定するか、ホームに戻ると破棄。
- softNo だけは日付付きで UserDefaults に残し、同日中の再セッションで −4 の減点に使う。翌日に消える(本体仕様の長期減衰は v1.0 で実装、プロトタイプでは省略)。

## 2. 画面ごとの仕様

### 2.1 ホーム(最小)

| 要素 | 仕様 |
|---|---|
| 主ボタン「今日の献立を決める」 | 画面下1/3に高さ64ptの大ボタン。片手の親指で届く位置 |
| 副ボタン「疲れた日」 | 主ボタンの上、高さ44pt、控えめな塗り。タップで mood=nil, timeLimit=quick, effort≤1, 1品完結のみ に固定して Omakase へ直行 |
| 前回決めた料理 | 上部にカード1枚。「昨日: 親子丼」。タップで Done |

### 2.2 気分・時間

| 要素 | 仕様 |
|---|---|
| 見出し | 「今日はどんな気分?」 |
| 気分チップ | がっつり / さっぱり / あたたまる / 麺・丼で済ませる / なんでも。単一選択。初期選択は「なんでも」 |
| 時間チップ | すぐ(〜15分) / ふつう(〜30分) / こだわらない。単一選択。初期選択は設定の「標準」(プロトタイプでは「ふつう」) |
| 主ボタン「候補を見る」 | 常に有効。何も触らなくても進める |
| 「スキップ」 | ナビゲーションバー右。既定値のまま Duel へ |
| 季節の初期値 | 12〜2月は「あたたまる」を薄くハイライト表示するだけ。選択はしない |

- チップは1タップで即反映。「決定」のような確認ボタンは置かない。
- この画面は 1タップ(チップ)+1タップ(候補を見る)、または 0タップ(スキップ)で抜ける。

### 2.3 どっち?(二択)

```
┌──────────────────────────────┐
│ 1/2                    どちらも違う │  ← 上部。回数表示と逃げ道
│                                  │
│  ┌──────────────────────────┐  │
│  │        [イラスト]          │  │  ← 左(上)カード: 画面高の 40%
│  │ 親子丼          15分  ⚡1 │  │
│  └──────────────────────────┘  │
│              vs                  │
│  ┌──────────────────────────┐  │
│  │        [イラスト]          │  │  ← 右(下)カード: 画面高の 40%
│  │ ペペロンチーノ  15分  ⚡1 │  │
│  └──────────────────────────┘  │
└──────────────────────────────┘
```

| 要素 | 仕様 |
|---|---|
| カード | 上下2枚。縦持ちで親指が届くよう上下配置(左右だと上側が遠い)。角丸20pt、影なし、枠線1pt |
| カード内容 | イラスト(4:3)、料理名(太字20pt)、調理時間、手間(⚡1〜3)。材料や説明は出さない。判断材料を増やすと迷う |
| 回数表示 | 「1/2」「2/2」。終わりが見えることが大事 |
| タップ | カード全面がヒット領域。タップで選択→0.25秒でカードが軽く拡大→次の対戦へ |
| 「どちらも違う」 | 右上に小さく。押すと両方 softNo に入り、pool から次の2枚を出す。round は進めない。同一セッションで2回まで、3回目は「おまかせで決める?」の確認シートを出す |
| 2回目の対戦 | 1回目の勝者が同じ位置(上)に残り、下に新しい挑戦者が入る。勝者が動かないことで「勝ち抜き」が伝わる |
| 2枚の選び方 | pool の上位から、系(和・洋・中・エスニック)と形態(1品完結/主菜)が重ならない組を優先。取れなければ系だけ、それも無理なら上位2件 |
| 触覚 | 選択時に `.impact(.light)`。連打防止に選択後0.3秒は入力を無視 |

### 2.4 決定

| 要素 | 仕様 |
|---|---|
| 演出 | 勝者カードが中央へ移動して拡大、0.6秒。スキップ可(タップで即終了) |
| 見出し | 「今日はこれ」 |
| 料理カード | イラスト大、料理名、調理時間、手間、費用目安 |
| 主な材料チップ | カード直下に材料名だけを横並びのチップで(3〜5個)。「冷蔵庫にあるか」を「これにする」の前に判断させる。タップしても何も起きない(プロトタイプ) |
| 緩和表示 | relaxation≥1 のとき、チップ下に1行:「30分の料理も含めました」「気分の条件を外して探しました」 |
| 主ボタン「これにする」 | 高さ56pt。押すと decided を確定し Done へ。履歴に日付付きで保存 |
| 「別の候補を見る(残り2)」 | 副ボタン。decided を softNo に入れ、Duel 1回目へ戻る。残り0で非活性にせず「おまかせで決める」に差し替える |
| 「おまかせで決める」 | テキストボタン。Omakase へ |

### 2.5 おまかせ(演出)

| 要素 | 仕様 |
|---|---|
| 候補 | pool から softNo を除いた上位6件 |
| 演出 | 6枚のカードが横に流れ、1.5秒で減速して1枚に止まる。タップで即停止 |
| 結果 | Decided と同じ画面。ただし「別の候補を見る」は出さず、「これにする」と「もう一回まわす(1回だけ)」のみ |
| 「疲れた日」からの流入 | Mood と Duel を飛ばしているので、結果画面に「疲れた日モード: すぐ・1品」と1行表示 |

### 2.6 決まった(最小)

- 料理名、イラスト、時間の目安、手間、主な材料(名前のみ。チェックすると買い物リストに入る。プロトタイプでは端末内の配列に追加するだけ)
- 「レシピを見る」: 料理名で検索を Safari に開くだけ。外部コンテンツは取り込まない
- 「食べた」: 履歴に記録してホームへ戻る
- 分量・手順の欄は無い。第3版でレシピを持たない方針にしたため

## 3. 候補選定(プロトタイプで実装する範囲)

```
func buildPool(session) -> [Dish]
  1. base = dishes.filter { form == .oneDish || form == .main }
  2. base = base.filter { !$0.tags.intersects(excludedIngredients) && !excludedDishes.contains($0.id) }
  3. 時間フィルタ: timeLimit → 上限 (15 / 30 / ∞)
  4. 気分フィルタ: mood != nil → moods.contains(mood)。mood == .noodleRice → form == .oneDish も要求
  5. if count < 3 { relaxation = 1; 上限を1段階広げて 3〜4 をやり直す }
  6. if count < 3 { relaxation = 2; mood = nil で 3〜4 をやり直す }
  7. if count < 3 { おまかせ直行(150件では発生しない。大豆除外でも緩和2で18件残る) }
  8. score(d) = moodMatch(+3) + favorite(+2) + eatenCount×0.5(上限+2)
              − recent7d(−5) − recent14d(−2) − softNoToday(−4)
              + seasonMatch(+1) + random(0...1.5)
  9. sort by score desc
```

- プロトタイプでは favorite と eatenCount は 0 でよい(履歴は「食べた」で溜まる)。
- 除外食材は設定画面がないので、コード内の定数で1〜2個入れて試す。

## 4. 計測(端末内ログ、プロトタイプは Console 出力で十分)

| イベント | 付随データ |
|---|---|
| session_start | 入口(決める / 疲れた日) |
| mood_selected | mood, timeLimit, スキップしたか |
| duel_shown | round, left, right |
| duel_picked | round, winner, loser, 表示からタップまでの秒数 |
| duel_both_no | round, 何回目の「どちらも違う」か |
| decided_shown | dish, relaxation, redrawsLeft |
| redraw | 残り回数 |
| omakase | 入口(疲れた日 / 決定画面 / 3回目の「どちらも違う」) |
| decided | dish, session_start からの秒数, タップ総数 |
| eaten | dish, decided からの経過時間 |
| recipe_opened | dish(「レシピを見る」が押された割合。高ければ材料メモだけでは足りない兆候) |
| abandoned | どの画面で離脱したか |

- 1週間の自己テスト後に、時間の中央値・タップ数・完了率・「どちらも違う」の頻度・緩和の発生率を集計する。

## 5. 1週間自己テストの合格条件

| 項目 | 合格 | 不合格なら見直す箇所 |
|---|---|---|
| 決定までの時間(中央値) | 30秒以内 | 演出の長さ、気分画面の要否 |
| 決定までのタップ数(中央値) | 4以下 | 気分画面の既定値、二択回数 |
| 「どちらも違う」の発生率 | セッションの30%以下 | pool の多様性ルール、スコアの乱数幅 |
| 「別の候補を見る」の発生率 | 決定画面到達の30%以下 | 二択2回で足りていない可能性。「3枚から1つ」案の試験を検討 |
| 決定した料理を実際に作った割合 | 50%以上 | 時間・手間の見積もり精度、料理データの魅力 |
| 同じ料理が7日以内に再登場 | 0回 | 重複回避のスコア |
| 緩和(relaxation≥1)の発生率 | 5%以下 | データの分布 |

- 期間中に「疲れた日」を最低2回使う。
- 毎回、決めた直後に「納得したか(はい/いいえ)」を1タップで自己記録する(プロトタイプ限定の質問)。納得率70%未満なら二択方式そのものを見直す。
- 「レシピを見る」を押した割合も見る。ほぼ毎回押しているなら、材料メモの見せ方を厚くする(それでもレシピ本文は持たない)。

## 6. 実装の順番(目安)

| 日 | 作業 |
|---|---|
| 1 | CSV → JSON 変換(主な材料名まで)、Dish モデル、同梱データ読み込み、buildPool とスコア |
| 2 | Mood 画面、Duel 画面(演出なし)、Decided 画面、遷移 |
| 3 | Done(最小)、買い物リスト(端末内配列)、履歴保存、softNo の日付管理、緩和表示 |
| 4 | Omakase 演出、疲れた日の直行、ホーム |
| 5 | 触覚・アニメーション・計測ログ、自己テスト開始 |

- 5日で自己テストに入る。画像は単色プレースホルダーのままでよいが、料理名・時間・主な材料は本番データを使う(魅力の評価に必要)。
- 自己テスト中に無料枠68件のイラスト生成(リスト設計§5)を並行して進める。

## 7. 決めていない点(自己テストで判断)

1. 二択カードの配置: 上下(推奨)か左右か。左右は横向きの写真が大きく見えるが、上側が遠い
2. 決定演出0.6秒が長く感じるか
3. 「どちらも違う」を目立たせるべきか。目立つと逃げやすく、隠すと詰まる
4. 気分画面をスキップした割合が高ければ、v1.0 で気分画面をホームに統合する(ホームにチップを置き、1画面減らす)
