## 0. 結論の要約

- **核は「試合そのもの」ではなく「自分がその試合をどう見たか」の記録。** 速報・スタッツは既存アプリ(FotMob、Club J.LEAGUE 等)に任せ、感想・写真・満足度・自分MVP など「自分側のデータ」に全振りする。
- **主戦場は「配信で海外サッカーを見る日本のファン」。** プレミアリーグとラ・リーガは必須、ブンデスリーガ・エールディヴィジ・Jリーグも対象。国内で配信されているリーグは網羅を目指す。
- **したがって日程・結果・順位表の自動取得は初期リリースから必要。** 海外リーグを手入力で追うのは現実的でない。データAPIを1本契約し、アプリと API の間に軽いキャッシュ用プロキシを置く。
- **データ源は TheSportsDB Premium($9/月、約1,400円)に決定。** 有料キーの検証(2026-09-20)で件数上限が外れ、7リーグのシーズン全試合と順位表が取れた。J1 の 2026-27 順位表だけ API 側に欠けているので、順位表は全リーグとも試合結果から自前で計算する。取得層は差し替え可能に作っておく。
- **チームロゴ・選手写真は初期リリースでは使わない。** API がロゴ URL を返しても権利の許諾ではない。チームカラー + 名前で推し感を出す。名前は API のチーム一覧から選ぶ。
- **写真は「観戦写真はアプリ内にコピー、推し選手の写真は写真ライブラリ参照」。推し選手は写真のみで、API の選手データは使わない。**(決定済み)
- **収益化は「無料 + Pro(年額サブスク と 生涯買い切りの2択)」で決定。** 理由は 3.5。データ費用が発生した場合は Pro の加入者で回収する。
- **複数チームはデータ構造だけ対応しておき、UIは1チームで出す。** 「推しを追加」は Pro の機能候補。

## 1. ユーザー体験と差別化

### 1.1 誰のためのアプリか

- 推しチームが1つある(多くて2〜3)。海外クラブが中心。
- 現地観戦は年に0〜数回。ほとんどは DAZN、U-NEXT、ABEMA などの配信で深夜・早朝に見る。
- 試合ごとに何か書き残したいが、SNSに毎回投稿するほどではない。
- 「今シーズン何試合見たか」「あの試合はいつだったか」を思い出したくなる。

### 1.2 国内で配信されているリーグ(2026-27シーズン、検索ベース)

配信サービスをそのまま「観戦方法」の選択肢にすると、記録の入力が速くなる。

| リーグ | 国内の主な配信(2026-27) | 備考 |
|---|---|---|
| プレミアリーグ | U-NEXT サッカーパック(独占) | DAZN・ABEMA は権利なし |
| ラ・リーガ | DAZN、U-NEXT サッカーパック | |
| ブンデスリーガ | DAZN(全試合)、ABEMA(毎節一部無料) | |
| エールディヴィジ | U-NEXT サッカーパック(独占) | |
| セリエA | DAZN、U-NEXT サッカーパック | |
| リーグ・アン | DAZN(独占) | |
| Jリーグ J1〜J3 | DAZN(全試合、2032-33まで契約報道)、一部 NHK・地上波 | 2026-27 から秋春制 |
| サウジ・プロリーグ | SPOTV NOW(独占との報道) | 第1回で「ドバイ」と書かれていたのはこれ |
| MLS | Apple TV(2026年から Apple TV 加入者向け、Season Pass は終了) | 日本での提供範囲は要確認 |
| チャンピオンズリーグ等 | 未調査 | 要確認 |

出典は末尾の参考リンク。配信権は毎年動くので、アプリ内に固定で持たず、観戦方法の選択肢はユーザーが編集できるようにする。

### 1.3 体験のループ

```
試合前   ホーム画面に「次の試合まで ○日」と対戦相手、順位 → 通知
   ↓
観戦     配信 / テレビ / 現地
   ↓
記録     「見た」を1タップ → 観戦方法を選ぶ → 一言(任意) → 写真(任意)
   ↓
振り返り タイムライン、シーズン集計、年間ベストゲーム
   ↓
次の試合が待ち遠しくなる
```

記録の入口を「一言だけでも成立する」ようにする。詳しく書きたい人には後から追記できる項目(MVP、満足度、印象的な場面)を用意する。

### 1.4 差別化の柱

| 柱 | 内容 | 既存アプリとの違い |
|---|---|---|
| 自分側の記録 | 感想、写真、チケット、満足度、自分MVP | 速報アプリは記録なし、公式アプリはポイント目的 |
| 配信も現地も同じ扱い | 観戦方法をタグとして持つだけ。どちらも「見た」 | |
| 積み上がる感覚 | シーズン集計、通算観戦数、年間まとめ | 推し活アプリの「積み上げ」をサッカーに持ち込む |
| 一人で完結 | アカウント不要、記録は端末内、SNS不要 | 開発者の既存アプリ(バイヤーノート、VINFIT)と同じ思想 |
| 推しの色に染まる | チームカラー2色でホーム画面・ウィジェットが変わる | 汎用アプリは白黒 |
| 推しチームだけを見る | 日程・結果・順位表を推しチームの視点に絞る | 速報アプリは全リーグが並ぶ |

## 2. 仕様を詰めたい点への回答

### 2.1 対象リーグ(決定: 海外必須、網羅志向)

優先度を3段階に分ける。API の対応範囲と契約プランで実際の範囲が決まる。

| 優先度 | リーグ | 位置づけ |
|---|---|---|
| A(必須) | プレミアリーグ、ラ・リーガ | これが取れない API は候補から外す |
| B(初期に入れる。第4回で確定) | ブンデスリーガ、エールディヴィジ、Jリーグ(J1〜J3) | 初期リリースは A + B の5リーグ |
| C(網羅のために順次) | セリエA、リーグ・アン、サウジ・プロリーグ、MLS、CL/EL | 国内で配信されているものを優先 |

アプリの構造としては「リーグ → チーム」の選択にし、リーグの追加は API 側の設定だけで済むようにする(アプリの更新なしで対象を増やせる)。

Jリーグは第2回で「対象に含める」と決まった。DAZN で全試合配信されており、2026-27 から秋春制になったので、シーズンの扱いは欧州と同じ跨ぎ年になる。

### 2.2 推しチームの登録(決定: プリセットから選択)

- チームは API のチーム一覧から選ぶ。リーグを選び、次にチームを選ぶ2段階。同名・類似名の混乱を避けるため、都市名や国旗ではなく「リーグ名 + チーム名」で表示する。
- チームカラーは API に含まれない場合が多いので、アプリ側で主要チーム分をあらかじめ持つ。無ければユーザーが2色を選ぶ。色はエンブレムを模した図形にしない。
- 呼び名(表示名)はユーザーが上書きできる。愛称で呼びたい人向け。
- 複数チームはデータ構造で対応しておき、初期リリースのUIは1チーム。「推しを追加」は Pro の候補。

### 2.3 試合日程・結果・順位表の取得(決定: 初期から自動取得)

**注意: 以下は 2026年9月19日時点の検索結果に基づく。各サービスの公式ページには作業環境のネットワーク制限で直接アクセスできなかった。契約前に必ず一次資料(公式の料金ページと利用規約)を確認すること。**

#### 候補の比較

| 提供元 | 無料枠 | 対応リーグ | 費用の目安 | 注意点 |
|---|---|---|---|---|
| API-Football (api-sports.io) | 100リクエスト/日。ただし無料枠は過去シーズン(2022〜2024)限定で当該シーズンは取れないという報告 | 全大会(J、サウジ、MLS を含むとされる) | Pro $19/月(7,500リクエスト/日)、Ultra $29、Mega $39(未確認) | 網羅志向なら第一候補。規約(モバイルアプリからの利用、キャッシュ、ロゴの扱い)は未確認 |
| football-data.org | 12大会(PL、ラ・リーガ、ブンデス、セリエA、リーグ・アン、エールディヴィジ、ポルトガル、チャンピオンシップ、ブラジル1部、CL、W杯、EURO)。10リクエスト/分。順位表あり | 有料でも欧州中心。J、サウジ、MLS は不明 | €12/月〜(30リクエスト/分)。選手・出場データは €29/月の別パック | **無料枠は商用利用不可という情報あり。** 有料アプリで使うなら有料プランが前提 |
| TheSportsDB | v1、無料キー(123)で30リクエスト/分。日程・結果・順位表あり。1回の応答が10件までという制限の報告あり | 広い。J1、サウジのリーグページあり | 無料。Premium $9/月で制限解除と v2 | **無料枠でもアプリ利用可と規約に明記(帰属表示が条件、商標ロゴは無加工)。** 精度と更新の速さは要検証 |
| Sportmonks | デンマーク・スコットランドのみ | 有料でリーグを選ぶ | €29/月(5リーグ)〜 | 網羅すると高くなる |

#### 判断

1. **第一候補は TheSportsDB の無料枠。** 無料のまま合法的にアプリで使え、帰属表示(「Data provided by TheSportsDB」)だけが条件。J1 とサウジも含む。ただしコミュニティ編集のデータなので、対象リーグの日程・結果・順位表を2〜3週間、他のソースと突き合わせて精度と更新の速さを検証してから採用を決める。
2. **足りなければ段階的に上げる。** 応答件数や速度が足りなければ TheSportsDB Premium($9/月)。精度そのものが足りなければ API-Football Pro($19/月、規約は要確認)。取得層を差し替え可能に作っておけば、切り替えはプロキシ側の変更で済む。
3. **アプリから API を直接叩かない。** 理由は3つ。APIキーをアプリに埋め込めない、リクエスト上限が全ユーザーで共有される、リーグ追加をアプリ更新なしでやりたい。Cloudflare Workers のような無料枠で足りる軽いプロキシを置き、リーグごとに日程は1日1回、結果は試合日に1時間おき程度で取得してキャッシュし、アプリにはキャッシュ済み JSON を返す。無料ソースでもこの構成は必要。
4. **順位表はシーズン全試合の結果からプロキシで計算する。** API の順位表は J1 で欠けていたので使わない。勝点・得失点差・総得点の順で並べ、リーグ固有の規則(直接対決など)は初期は無視する。1日1回更新で足りる。
5. **自動取得したデータはユーザーが手動で上書きできる。** 延期・中止・データの誤りに備える。手動で直した行は同期で上書きしない。無料ソースほどこの保険が効く。
6. **API にないリーグ・大会(親善試合、地域リーグなど)は手動登録で対応する。** 手動登録は最初から必要。

#### 「Webで見られる情報なのに、なぜ無料の API がないのか」への回答

試合の日程・結果・順位は「事実」なので、それ自体は著作権の対象になりにくい。値段が付いているのは事実そのものではなく、「毎日欠かさず、正確に、全リーグ分を、機械で読める形に整えて配る」作業に対してである。Web のサイトは人が読む前提で作られていて、機械で取ることは規約で禁じていることが多い(Jリーグ公式サイトはその例)。だから無料で手に入るものは、次のどれかになる。

| 種類 | 例 | 使えるか |
|---|---|---|
| コミュニティが善意で集めたもの | TheSportsDB、openfootball | 使える。精度と更新速度は保証されない |
| 非公式・黙認されているもの | ESPN の非公開 API、各サイトのスクレイピング | 本番では使わない。いつ止まっても文句を言えず、審査で問題になる可能性もある |
| 有料 API の試用枠 | football-data.org の無料枠、API-Football の無料枠 | 開発用。前者は商用利用不可の情報、後者は過去シーズン限定の報告 |

無料の選択肢の比較:

| ソース | 対象 | 条件 | 向き不向き |
|---|---|---|---|
| TheSportsDB | 欧州主要リーグ、J1〜J3、サウジ、MLS ほか多数。日程・結果・順位表 | 帰属表示。無料キーは件数上限あり(検証済み)。**Premium($9/月)で上限が外れることを検証済み** | **採用。** J1 の順位表は自前計算で補う |
| openfootball(GitHub) | プレミア、ラ・リーガ、ブンデス、セリエA、リーグ・アン、エールディヴィジ等。JSON | パブリックドメイン。更新はボランティア次第で不定期。Jリーグなし | 欧州の検証用・保険。順位表は結果から計算 |
| ESPN 非公開 API | 非常に広い。順位表・日程あり | 許諾なし、無保証 | 検証時の突き合わせ用に限る |
| football-data.org 無料枠 | 欧州4リーグ + セリエA、リーグ・アン、CL 等 12大会 | 商用利用不可の情報。10リクエスト/分 | 開発用 |
| API-Football 無料枠 | 全大会 | 当該シーズンは取れない報告。100リクエスト/日 | 開発用にも不向き |
| Jリーグ公式サイト・データサイトのスクレイピング | J1〜J3 | 無断転載禁止 | 採らない |
| Wikipedia | 各リーグのシーズン記事に結果表 | CC BY-SA。構造が不安定で機械読み取りに向かない | 採らない |

結論: TheSportsDB を第一候補に検証し、費用は必要になったときだけ $9 → $19 と上げる。「欧州4リーグなら無料か」については、football-data.org の無料枠は商用不可の疑いがあるので本番では使わず、TheSportsDB で欧州も J もまとめて取る方が単純。

#### 「TheSportsDB のような API を自前で作れないか」への回答

API を返す部分は自前で作れるし、実際に作る(キャッシュ用プロキシがそれ)。作れないのは中のデータの方。TheSportsDB の価値はデータベースに試合・スコア・順位を入れ続けている作業にある。

自前でデータを入れる場合、初期の7リーグ(プレミア、ラ・リーガ、ブンデス、エールディヴィジ、J1〜J3)で1シーズン約2,500試合。開幕時の日程入力は数十時間で済むが、その後は毎週60〜80試合の結果更新が週末の深夜〜早朝に発生し、放送都合のキックオフ時刻変更や延期も追う必要がある。通知機能があるので時刻の誤りは直接クレームになる。月 $9〜19 と、シーズン中毎週末の数時間の作業との交換になり、運用負担を抑える方針と合わない。

結論: プロキシ(API)は自前、データは購入。手入力は「API に無い試合を補う手段」として残し、全部を手で入れる前提にはしない。

#### 「アプリが Safari のように Web ページを読み取ればよいのでは」への回答

技術的には可能(HTML を取得して解析する、いわゆるスクレイピング)。ただし採らない。

1. **規約違反になりやすい。** 多くのサイトは利用規約で自動取得・転載を禁じている。Jリーグ公式サイトは無断転載禁止を明記。Google 検索結果の自動取得も Google の規約違反。端末上で読むかサーバーで読むかは規約上の扱いにほぼ関係ない。API は「機械向けに許可された入り口」、ページの読み取りは「人向けの入り口に機械で入る」行為。
2. **壊れやすい。** HTML の構造が少し変わるだけで読み取りが壊れる。アプリ側で読んでいると、修正のたびに審査を通す必要があり、日単位で止まる。プロキシ側で読めば審査は不要になるが、規約の問題は残る。
3. **審査で止まる可能性。** App Store 審査ガイドライン 5.2.2(第三者のコンテンツの無断使用)に触れる。他サイトの情報を取り込んで表示するアプリのリジェクト事例がある。

代わりにやること:

- **自動取得は許可された API(TheSportsDB など)だけ。** API で取れない試合は手動登録。
- 「公式サイトをアプリ内ブラウザで開くボタン」も検討したが、不要と判断(第4回)。
- **公式 iCal をユーザー自身のカレンダーに入れ、アプリが EventKit で読む案**は、再配布に当たらないと考えられるが規約原文が未確認なので候補のまま。

### 2.4 自動取得する部分と手動入力できる部分

| データ | 取得 | 備考 |
|---|---|---|
| リーグ・チーム一覧 | 自動(API) | プロキシでキャッシュ。アプリ更新なしで追加可 |
| 試合日時・対戦相手・ホーム/アウェイ・大会 | 自動(API)、手動で追加・上書き可 | |
| スコア・勝敗 | 自動(API)、手動で上書き可 | 試合終了後に反映。速報は目指さない |
| 順位表 | 自動(シーズン全試合の結果から自前計算) | API の順位表は使わない。J1 で欠落があったため |
| 観戦方法・視聴サービス | 手動 | 選択肢はユーザーが編集可 |
| 一言・感想・写真・チケット | 手動 | |
| 自分MVP・満足度・印象的な場面 | 手動 | 自分MVP の候補にスカッドを出せると楽 |
| 推し選手の写真 | 手動(写真ライブラリから選ぶ) | 決定: 写真のみ。API の選手データは使わない |
| シーズン集計・年間まとめ | 記録から自動算出 | |
| 通知 | 取得した日程からローカル通知 | プッシュサーバーは持たない |

原則: **自動化するのは「試合の事実」だけ。「自分の気持ち」は常に手動。**

### 2.5 チームロゴ・選手画像(方針維持: 初期は使わない)

- API がロゴや選手写真の URL を返す場合があるが、それは API 提供者が権利を持っている保証ではない。クラブのエンブレムは商標で、リーグやクラブが私的使用以外を許可制にしている(Jリーグは明文化されている。欧州クラブも同様の扱いと考える)。
- App Store 審査 5.2.1 でスポーツロゴを使ったファンアプリのリジェクト事例が複数ある。
- 代わりにチームカラー2色とチーム名で表現する。名前は API の一覧から選んだ文字列を事実として表示する。
- **推し選手は写真のみ(決定済み)。** ユーザー自身が写真ライブラリから選んだ写真を参照して表示する。API の選手データや公式の選手写真は使わない。名前を添えたければユーザーが自由入力する。

### 2.6 写真の保存(決定)

| 種類 | 保存方法 | 理由 |
|---|---|---|
| 観戦写真・チケット | アプリ内にコピー(縮小版も生成) | 書き出しとバックアップが確実。写真ライブラリから消しても記録に残る |
| 推し選手の写真 | 写真ライブラリへの参照(PhotoKit の識別子) | 差し替えが多く、容量を食わせたくない。参照切れ時はイニシャル表示に戻す |

## 3. 最小構成(初期リリース)の提案

### 3.1 技術方針

- **アカウントなし。** 記録は端末内(SwiftData)。バックアップは iCloud(CloudKit プライベートDB)。
- **サーバーは「試合データのキャッシュ用プロキシ」だけ。** ユーザーの記録はサーバーに送らない。既存アプリのプライバシーポリシーと同じ思想を保てる。
- **通知はローカル通知のみ。**
- SwiftUI、SwiftData、PhotosPicker、UserNotifications、WidgetKit、StoreKit 2。プロキシは Cloudflare Workers + KV(無料枠)を想定。

### 3.2 データモデル(たたき台)

```
Competition(リーグ・大会)
  id, externalId, name, country, seasonStartMonth, isActive

Team
  id, externalId?, competitionId?, name, displayName(呼び名),
  primaryColor, secondaryColor, isFavorite, createdAt,
  favoritePlayerPhotoAssetId?(写真ライブラリ参照), favoritePlayerCaption?

Match
  id, externalId?, competitionId?, kickoffAt,
  homeTeamId, awayTeamId, favoriteTeamId,
  homeGoals?, awayGoals?,
  status: scheduled | inPlay | finished | postponed | cancelled,
  source: api | manual, manuallyEdited: Bool

Standing(順位表。プロキシが結果から計算したもののキャッシュ、保存は最新のみ)
  competitionId, season, rows[ position, teamId, played, won, drawn, lost, gf, ga, points ]

Viewing(観戦記録。Match と1対1)
  id, matchId,
  method: stadium | streaming | tv | notWatched,
  service?(DAZN / U-NEXT / ABEMA / SPOTV NOW / Apple TV / 地上波 / その他。編集可),
  oneLiner, note?, satisfaction?(1..5), myMvp?(選手名), highlight?,
  createdAt, updatedAt

Photo(観戦写真・チケット)
  id, viewingId, kind: photo | ticket, fileName(アプリ内コピー), takenAt

派生(保存しない): シーズン集計、通算成績、年間ベストゲーム
```

- `Match.manuallyEdited` が true の行は API 同期で上書きしない。
- シーズンは `Competition.seasonStartMonth` で決める。欧州と(2026-27からの)Jリーグは跨ぎ年、MLS は暦年(MLS も暦の変更が報道されているので要確認)。

### 3.3 画面構成

1. **ホーム**
   - チームカラー背景。次の試合(相手、日時、大会、ホーム/アウェイ)とカウントダウン。
   - 直近の結果と自分の一言。
   - 順位表の抜粋(推しチームの前後3チーム程度)。タップで全体。
   - 推し選手の写真(ユーザーが選んだ1枚。キャプションは任意)。
   - 今シーズンの観戦数と勝敗。
2. **日程・結果**
   - 推しチームの試合だけをシーズン順に。過去は結果と観戦方法アイコン、未来は日程。
   - 未記録の試合には「見た」ボタン。
   - 手動で試合を追加するボタン(API にない試合用)。
3. **記録(試合詳細)**
   - スコア(API 取得済みなら表示のみ、編集可)、観戦方法と視聴サービス、一言、写真、任意項目(満足度、自分MVP、印象的な場面)。
   - 一言だけ入れて閉じても保存される。
4. **振り返り**
   - シーズンごとの観戦数、現地/配信の内訳、観戦した試合の勝敗、視聴サービス別の本数。
   - 写真グリッド。
   - 年間まとめ(シーズン終了後に「今年のベストゲーム」を自分で選ぶ)。
5. **設定**(歯車)
   - 推しチーム・推し選手の写真の編集、観戦方法の選択肢の編集、通知タイミング、Pro の購入、書き出し、データ提供元の表示、プライバシーポリシー。

### 3.4 機能のスコープ分け

| 区分 | 機能 |
|---|---|
| **初期リリース(必須)** | リーグ → チーム選択(1チーム)と推し選手の写真 / 日程・結果・順位表の自動取得 / 手動での試合追加と上書き / 観戦方法と視聴サービス / 一言と長文メモ / 観戦写真とチケット / ホームのカウントダウン / 試合前ローカル通知 / シーズン集計 / iCloud バックアップ / 書き出し(CSV + 写真) |
| **次のリリース候補** | 満足度・自分MVP・印象的な場面 / 年間ベストゲームと年間まとめ / ウィジェット(カウントダウン、次の試合) / 複数チーム / 対象リーグの拡大(優先度C) |
| **検討中** | ライブ活動(Live Activities)でのスコア表示(速報アプリ化しないよう注意) |
| **やらない** | SNS投稿の必須化 / 他ユーザーとの交流 / 公式ロゴ・公式選手写真 / 速報・ライブスコアの追求 / 広告 |

推し選手は写真1枚とキャプションだけなので、初期リリースに含める(上の必須欄の「推しチーム選択」に含む)。

### 3.5 収益化(決定: 無料 + Pro の年額 / 生涯)

「買い切りで買ってくれるか」への率直な見立て:

- **買い切りは「日記・手帳」として売るなら成立する。** 推し活手帳やスポーツ観戦記録の類は、数百円〜千円台の買い切りで売れているジャンル。ただし無料から有料への転換率は数%が普通で、収入は「ダウンロード数 × 数% × 単価」になる。
- **サブスクは「毎月データが流れてくる」ことが根拠になる。** 今回は API 費用が月額で固定発生するので、事業としてはサブスクの方が筋が通る。一方で推し活層はすでに DAZN や U-NEXT に月2,600〜4,200円払っており、月額の追加には敏感。月数百円でも「また月額か」となりやすい。
- **どちらか一択にする必要はない。** App Store は自動更新サブスクと買い切り(非消耗型)を同じアプリで併売できる。

推奨:

1. **無料で「1チーム、自動取得、記録、集計」まで全部使える。** まず習慣化してもらう。データ費用(月 $9〜19)は当初自腹で持つ。
2. **Pro は「年額」と「生涯買い切り」の2択。** 月額は置かない。年額は月額換算で百円台に見える価格に、生涯はその3〜4年分程度に設定する。サブスクを嫌う層は生涯を選び、試したい層は年額(無料トライアル付き)を選ぶ。**具体的な価格は、データ源の費用が決まってから決める(第4回)。** 無料ソースで足りるなら低め、有料 API が必要ならその年額を数十人で回収できる水準にする。
3. **Pro に入れる機能:** 推しチームの追加、写真枚数の上限解除、年間まとめの PDF 書き出し、ウィジェットの追加スタイル、テーマの細かい調整。データ取得そのものは無料側に残す(取得を有料にすると無料版が成立しない)。
4. **広告は入れない。** 推しの色で染めた画面に無関係な広告が出る体験は、このアプリの価値を直接削る。

損益の目安(仮の数字。公開リポジトリなので実績値は書かない):

| 前提 | 値 |
|---|---|
| API 費用 | TheSportsDB Premium なら年 ¥16,000、API-Football Pro なら年 ¥34,000 程度 |
| Pro 年額を ¥1,200 とした場合の損益分岐 | TheSportsDB Premium で約14人、API-Football Pro で約28人の継続加入 |
| Pro 生涯を ¥3,600 とした場合 | 5〜10人で1年分 |

API 費用は利用者数にほぼ比例しない(プロキシでキャッシュするため)ので、加入者が増えるほど楽になる。加入者ゼロでも持ち出しは年1〜3万円台に収まる。

### 3.6 継続費用の見積もり

| 項目 | 初期リリース | 備考 |
|---|---|---|
| Apple Developer Program | 年額(既存アプリと共通) | |
| データ API | $9/月(TheSportsDB Premium。決定) | 約1,400円/月、年 ¥16,000〜17,000 |
| キャッシュ用プロキシ | 0円(Cloudflare Workers 無料枠を想定) | 1日10万リクエストまで。1,000ユーザーが1日20回取得しても収まる |
| ユーザー記録のサーバー | 0円(持たない) | |
| 画像ストレージ | 0円(端末とユーザーの iCloud) | |

## 5. 決めてほしいこと(第5回)

これまでに決まったこと:

- 初期リリースのリーグはプレミア、ラ・リーガ、ブンデス、エールディヴィジ、J1〜J3 の5つ。セリエA・リーグ・アン・サウジ・MLS は順次。

- 順位表を入れる。「公式サイトで見る」ボタンは入れない。
- 収益化は無料 + Pro(年額 / 生涯)。価格はデータ源の費用が決まってから。
- データ源は無料(TheSportsDB)から始め、必要になったときだけ $9 → $19 と上げる。検証スクリプトを用意した。
- アプリ名は後で決める。

次にやること:

1. **修正版スクリプトで残り3点を確認する。** `python3 verify_thesportsdb.py --key <キー> --leagues ラ・リーガ,エールディヴィジ,J1` で、ラ・リーガとエールディヴィジが正しく引けるか、チーム一覧が取れるか、J1 の順位表が結果から計算できるかを見る。
2. **Pro の価格を決める。** データ費用が年 ¥16,000〜17,000 と決まったので、たたき台は年額 ¥1,200、生涯 ¥3,900。年額なら約14人、生涯なら5人で1年分をまかなえる。
3. その後、画面ごとの詳細仕様(ワイヤーフレーム相当)とプロキシの API 設計に進む。
